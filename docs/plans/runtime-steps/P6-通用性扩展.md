# P6 Research Skill 通用性验证 — 详细步骤

> 所属：`docs/plans/Mybot通用AgentRuntime与办公自动化SkillPack整合方案.md`
> 状态：仅规划，未执行。2026-07-14 收缩为 1–2 天 Research 最小闭环，并作为 P8 Subagent 第二验证场景。
> 阶段出口：不修改 Runtime 核心接口即可接入 Research Skill，复用 manifest、policy、artifact、trace、eval 与可选 Subagent 编排。

---

## S6.1 最小 Research Skill

新增：

```text
nanobot/skills/research/
├── SKILL.md
├── skill.yaml
├── references/
└── evals/
```

工作流只覆盖：

1. 搜索并收集来源。
2. 写 `sources.json`。
3. 基于来源写 `research_report.md`。
4. 校验引用与来源覆盖。

不做完整研究产品、知识库、向量数据库或复杂 UI。

## S6.2 Runtime 复用

- Web/network 使用现有工具与 SSRF 硬边界。
- 远程访问、登录态操作和外发动作走 P3 policy/approval。
- `sources.json` 和报告进入 P4 Artifact Store，report lineage 指向 sources。
- P5 trace/eval 使用同一事件和 metric 接口，不新增 research 专属 Runtime 通道。
- manifest 无效、Skill disabled 等语义与两个 Office Skill 一致。

## S6.3 不可信来源安全

- 网页正文和搜索摘要统一视为 untrusted content。
- 不承诺检测全部 prompt injection。
- 红队 case 断言恶意来源无法诱导读取敏感文件、越界写入或未确认外发。
- 报告只引用 sources 中登记的来源。

## S6.4 Subagent 验证

父 Agent 可根据提示和计划决定是否并行派生子 Agent 收集不同来源：

- 最多 5 个直接子 Agent，禁止嵌套。
- 权限继承父任务且只能收紧。
- 每个 child 有 token、时间和工具预算。
- child 只返回结构化摘要、来源与 artifact 路径，父 Agent 负责最终报告。
- 使用时必须记录父子 trace，并与单 Agent 顺序收集比较时长和 token 成本。

Research 不强制每次使用 Subagent；父 Agent 可以选择单 Agent 路径。

## S6.5 接口收敛

接入时记录所有 Office 私有假设：

- artifact type 是否写死 docx/pptx。
- policy 是否依赖 Office 命令。
- eval 是否强制 DSL/batch。
- trace 是否缺少通用 child/source 事件。

只修复真实阻塞点，不提前构建通用工作流引擎。

## 定向测试

- 单 Agent 生成 sources/report，引用可核对。
- 恶意来源不能造成越权副作用。
- Research Skill disabled/invalid/unavailable 行为与 Office Skill 一致。
- 使用 child 时权限只紧不松、预算生效、父子 trace 完整。
- 单 Agent 与含子 Agent 路径均产出相同类型的最终 artifact，并记录成本/时长。

## 阶段出口检查

- [ ] Research Skill 在 1–2 天范围内形成最小闭环。
- [ ] policy/artifact/trace/eval 无 Office 私有分支即可复用。
- [ ] 不可信来源安全指标为越权副作用和泄漏次数 0。
- [ ] Subagent 为可选执行策略，使用时治理与对比数据完整。
