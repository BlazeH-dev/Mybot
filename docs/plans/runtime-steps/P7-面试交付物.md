## 3. 固定 Demo

```text
Skill 开关
→ 仅规划/执行按钮 + 普通复杂任务自动 plan-and-execute
→ verified facts 与 Office 产物
→ expire_and_deny 批准/超时拒绝
→ 外部修改触发 file_conflict
→ input snapshot 与 lineage
→ kill 后 completed/pending/uncertain 恢复
→ Subagent 预算、隔离产物与父子 trace
→ eval 与单/多 Agent 成本时长对比
```

- 真跑至少三遍，记录时长、失败兜底和依赖。
- 准备完整演示与 3 分钟摘要，不把共享 workspace 文件租约作为必需步骤。
- GIF/短视频和架构图入库。

## 4. 表达与追问

准备 30 秒、3 分钟和 10 分钟三档讲法；每个回答标注代码、测试或指标证据。

必须能回答：

- 为什么基于 nanobot 二开，哪些代码是自己写的？
- 为什么不用 LangChain/LangGraph/复杂工作流？
- 如何防数字幻觉、注入后果和越权副作用？
- 含 LLM 的系统如何做确定性测试？
- HITL 等待时模型是否运行，三档超时为何不同？
- checkpoint 为什么不是 exactly-once？
- 用户/IDE 并发修改如何避免覆盖？
- Subagent 如何限制数量、权限、预算、上下文和产物？文件租约为何选做？
- 多模型、成本和缓存优化的数据结论是什么？

简历项目描述不超过 4 行，只写已完成且有数字支撑的能力。
