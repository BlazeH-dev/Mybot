# P7 Benchmark、可观测与最终结果展示

> 状态：持续维护，公开 benchmark、Langfuse Python SDK 接入、OfficePython 通用化和一键入口尚未完成。
> 目标：让陌生人 10 分钟内理解项目、复现核心证据，并能从 README 进入一个真实 Langfuse Dataset Run 下钻；不制作 Demo、视频或独立答辩稿。

## 1. 一键入口

```bash
nanobot benchmark prepare --profile office-smoke
nanobot benchmark prepare --profile office-release
nanobot benchmark estimate --profile office-release --model-preset gpt-5-6-luna
nanobot benchmark run --profile ci
nanobot benchmark run --profile office-smoke --model-preset gpt-5-6-luna
nanobot benchmark run --profile office-release --model-preset gpt-5-6-luna --presentbench-sample 50 --confirm-cost
nanobot benchmark export --dataset-run <langfuse-dataset-run-id>
```

- `ci`：deterministic eval、cassette、代表性红队和 adapter contract；无 API Key、无网络、不开 Langfuse。
- `prepare`：准备外部 Office 资产和独立 benchmark venv，校验 revision/SHA/license，并创建/校验不可变 Langfuse Dataset；不创建本地 Dataset CRUD。
- `estimate`：在调用模型前给出 full/50%/25% 预算并要求确认；实际 token/cost 由 Langfuse generation 统计。
- `run`：薄封装 Langfuse Python SDK `run_experiment()`，task callback 执行 Luna Agent 和对应 Skill；并发、Trace、错误隔离、Dataset Run、item/run evaluator 与 Score 均由 SDK/Langfuse 管理。
- `export`：只读取一个已完成且审核齐全的 Langfuse Dataset Run，生成去敏结果快照和 README 受控区块。

删除 `benchmark status/resume/audit-sync/publish`、单 active run 锁、本地 run/score 状态机和 benchmark WebUI。运行进度、失败 case、Score、成本和人工审核直接在 Langfuse 查看；失败 case 首版以带 `parent_run_id` 的 retry Dataset Run 重跑，不自建断点恢复。

`office-smoke` 固定三套 benchmark 各 4 个 case、两个 Skill 同题，12 个 experiment traces 全部进入 Annotation Queue。`office-release` 跑 OCB 全量、固定 OfficeBench Office subset，PresentBench 在三档成本确认后选择独立 Dataset/series。两者都要求外部预装且版本锁定的 LibreOffice，以及日本区 Cloud 写入、flush、API 回读和 deep link smoke。

## 2. 评估与结果归属

| 内容 | 执行位置 | 唯一记录位置 |
| --- | --- | --- |
| deterministic/cassette/Policy/OCC/HITL/恢复 | 本地 pytest/CI | CI 结果与 committed deterministic snapshot |
| OfficeBench 官方 evaluator | Experiment Runner 进程中的 SDK evaluator | Langfuse `official_score` |
| OpenXML/渲染/文件 hard gate | Experiment Runner 进程中的 SDK evaluator | Langfuse item Score；代码回归仍由本地 CI 判定 |
| OCB Terra Judge | Langfuse Custom LLM-as-a-Judge | Langfuse `mybot_score` + reasoning |
| PresentBench 内容/视觉 Judge | Langfuse Custom LLM-as-a-Judge；视觉不支持时仅该维度本地 SDK evaluator | Langfuse `mybot_score` + reasoning |
| 人工审计 | Langfuse Annotation Queue | Langfuse Score/comment/reviewer |
| 成本、延迟、成功率、趋势 | Langfuse generation/Dashboard | Langfuse |

OCB/PresentBench 使用 Langfuse LLM Connection 连接 OpenAI-compatible 的 `gpt-5-6-terra`，仍标记 `Mybot evaluation`，不能称为官方分数或 `official-comparable`。三套结果不合成总分；报告必须分别给出 `supported/total`、`passed/total`、`passed/supported`，unsupported 的成本和耗时单列。

Git 中只保留发布快照：

```text
benchmarks/latest.md                 结果类型和 Langfuse deep link 索引
benchmarks/runtime/latest.{json,md} deterministic/fake-provider 证据
benchmarks/office/latest.{json,md}  从已审核 Dataset Run 导出的真模型结果
benchmarks/exports/<run-id>.json     去敏、不可编辑的 Langfuse 导出快照
```

原始 benchmark 数据、完整 Trace、Office 文件和不能上传的渲染媒体保存在外部缓存。Score、Judge reasoning、人工审核和跨 run 趋势不复制进本地数据库；导出快照只服务 Git/README 展示。

## 3. Office Skill 对比

P1.1 完成后，对 `officecli` 与 `office-python` 分别运行同一个 Langfuse Dataset 和 evaluator config：

- capability coverage：`supported/unsupported/passed/failed`；
- common-task quality：OfficeBench official 或 OCB/PresentBench Mybot score、人工 Score、Token/cost、LLM/tool latency、tool success 和 Agent steps；
- 使用 Dataset Run comparison、Score Analytics 和 Dashboard 查看差异，不在 Mybot 重做跨 run 图表；
- OCB 证明文件理解，OfficeBench Office subset 证明 Word/Excel 创建编辑，PresentBench 证明 PPT 创建和视觉质量。

OfficePython 是公平 Python baseline，不得通过 Dataset、prompt 或 evaluator 配置偏袒 OfficeCLI。

## 4. Langfuse 与 Mybot UI

Langfuse 固定使用日本区 Cloud `https://jp.cloud.langfuse.com`：

- Python SDK 随 Mybot 默认安装并锁定版本（`langfuse>=4.14.0`），负责 OTel observation、masking、batch/retry/flush、Experiment Runner 和 Scores API。
- Langfuse UI负责 Trace/Sessions、Datasets/Dataset Runs、Experiments、Scores、成本/延迟 Dashboard、Monitors、Annotation Queue 和失败下钻。
- Mybot 不建 Trace 查询、Dataset/Experiment CRUD、benchmark 状态面板、Score 管理、跨 run 图表或标注 UI；WebUI 只保留当前 Runtime 的 plan/approval/artifact/checkpoint，并提供 Langfuse deep link。
- `observability.langfuse.enabled=false`（默认）时保留现有 JSONL TraceHook 作为本地调试路径；启用后切换到 Langfuse SDK 并停写 JSONL，二者互斥。Cloud 关闭或故障不阻塞普通 Runtime；smoke/release 把 Cloud preflight 作为硬门。
- `langfuse.openai` drop-in 在 provider 从 config 设置环境变量后自动追踪 OpenAI/DeepSeek/GPT-5.6 的所有 LLM 调用；`runner._request_model()` 和 `runner._run_tool()` 逐调用创建 generation/tool observation。
- LLM Connection 中保存 Terra 中转站 Key/Base URL；Mybot 只保存 Langfuse SDK 项目 Key。两类密钥都不得进入前端、仓库、导出快照或 Trace。
- 只上传许可证允许且已脱敏的 metadata/rubric/media；公司或敏感内容在合规审查前关闭 Cloud。
- Cloud 模式不要求本机安装 Redis、MinIO、ClickHouse 或 PostgreSQL。
