# P3.1 WebUI Workspace / Git Worktree 隔离

> 状态：选做，未排期、未实现（2026-07-22 完成方案收敛）。
> 定位：独立工作区增强，不是 Runtime Core，也不是 P3 OS sandbox 的安全边界，不阻塞 P6/P7 主线或项目冻结。
> 启动条件：冻结前必做完成后，真实多聊天 Git 冲突证明收益高于实现和长期维护成本，并由用户明确提高优先级。
> 选做出口：若启动，localhost WebUI 可为新聊天显式创建 per-chat worktree，会话/fork/重启后绑定可恢复，自动清理不丢失 dirty 状态或新 commit。

## 1. 目标与非目标

P3.1 若被启动，只解决 Git 项目聊天之间的工作目录和分支冲突：

- 用户可在新聊天创建前选择 `Direct` 或 `Worktree`。
- Worktree 聊天从确定 commit 开始，不直接修改用户当前 checkout。
- 聊天 fork 使用新分支/新 worktree，不与源聊天共享可写工作树。
- 聊天删除时仅自动清理可证明没有新工作的 worktree。

首版明确不做：

- 不将 worktree 宣传为 sandbox、容器或恶意代码隔离。
- 不自动复制 tracked/untracked/ignored 未提交文件。
- 不自动 `commit/merge/push/rebase`，不提供 Agent Core Git 写工具。
- 不自动初始化 submodule 或 Git LFS 网络资产。
- 不为 Subagent 创建嵌套 worktree；child 继续使用 P8 artifact root。
- 不覆盖 CLI、其他 channel、MCP server 或 gateway 自身工作目录。

## 2. 用户与会话契约

### 新聊天

- Composer 项目控件增加 `isolation_mode=direct|worktree`，默认 `direct`，WebUI 记住最近选择但不改变旧会话。
- `worktree` 只在 localhost project controls 可用时出现；非 Git 目录返回 `worktree_not_git_repo`。
- 服务端解析用户选择路径所在的 repo root、Git common dir、当前 branch 和 `HEAD`。如果选择的是仓库子目录，新 `WorkspaceScope.project_path` 指向 worktree 中的对应相对子目录。
- tracked/untracked 变化不会出现在新 worktree。服务端先返回 `worktree_head_confirmation_required`及变化数量，用户确认“从 HEAD 创建”后才继续。ignored 文件不参与 dirty 判定，也不复制。

### 聊天期间

- Worktree 绑定一旦持久化，该聊天不再允许切换项目或 isolation mode；仅允许在非运行状态下切换 `restricted|full`。
- WebUI 以原项目路径分组聊天，同时展示 worktree 标识和 `mybot/chat-<chat_id>` 分支；文件预览和工具执行使用 effective worktree path。
- `Full Access` 仍表示用户显式关闭本地 OS sandbox；worktree 本身不承诺 Full Access 下无法访问原仓库。

### 聊天 fork

- Direct 聊天继续 fork 为 Direct。
- Worktree 聊天只有在源 worktree clean 时才允许 fork；新 worktree 以源 `HEAD` 为 base commit，不复制未提交 diff。
- worktree 创建成功但 session/transcript fork 失败时，因新 worktree 尚无变化，控制面立即安全回收它。

## 3. 持久化与模块边界

新增 `nanobot/workspaces/worktrees.py`：

```text
WorktreeManager
  inspect_source(path)
  create(chat_id, source_path, expected_head)
  resolve(binding)
  fork(source_binding, new_chat_id)
  cleanup(binding)
  list_managed()
```

受控路径：

```text
~/.nanobot/worktrees/<repo_id>/<chat_id>/
~/.nanobot/worktrees/registry.json
```

- `repo_id` 使用 resolved Git common dir 的稳定 SHA-256 摘要，不把仓库名直接拼入受控路径。
- registry 使用原子替换、`0600` 文件权限，至少记录 `worktree_id/chat_id/source_path/repo_root/common_dir/worktree_root/project_relative_path/branch/base_commit/status`。
- registry read-modify-write 与 create/fork/cleanup 使用跨进程 advisory lock 串行化，避免并发聊天创建或删除时丢更新；操作先落 `creating|removing` 中间状态，成功后再提交稳定状态。
- branch 固定为 `mybot/chat-<chat_id>`；碰撞、路径逃逸、bare repo、缺失 Git binary 和不一致 `HEAD` 都结构化 fail closed。
- Worktree 创建/删除由宿主控制面以固定 Git argv 执行，不经过 Agent `exec`，不接受模型提供的 branch/path/git flags。
- 启动时只对 registry 和 `git worktree list --porcelain` 做对账，不自动 `prune --force`；遗留 `creating|removing`、缺失或不一致项按可证明结果恢复，否则标记为 `missing|attention_required`。

会话持久化增加服务端 `workspace_binding`，与客户端可提交的 `workspace_scope` 分离。客户端不能伪造 common dir、worktree root、branch 或额外 sandbox roots；`WorkspaceScopeResolver` 必须从 session metadata + registry 复核有效绑定，绑定丢失时不得静默回退原仓库。

## 4. 删除与保留

聊天删除前读取 worktree binding，清理结果不影响聊天/session 删除，但必须返回结构化状态：

- `removed`：worktree clean 且 `HEAD == base_commit`，使用非 force `git worktree remove` 后删除 Mybot 分支。
- `preserved_dirty`：存在 tracked 或 untracked 变化。
- `preserved_commits`：`HEAD != base_commit`，不管 commit 是否推送/合并都保留。
- `attention_required`：Git/registry/path 对账失败，不执行破坏性清理。

WebUI 提供精简的 managed worktree 列表，显示源项目、branch、path、dirty/base 状态；只有满足同一安全判定的项可点击清理，首版不提供 force remove。

## 5. 实施顺序

### W0：数据契约与 Git 预检

- 定义 isolation mode、public scope payload、server binding、registry schema 和结构化错误。
- 实现 repo/subdir/HEAD/dirty 只读预检，先补单元测试。

### W1：WorktreeManager 与安全清理

- 实现 create/resolve/fork/cleanup/list、跨进程 registry lock、原子持久化和中间状态对账。
- 使用真实临时 Git repo 验证分支、子目录映射、并发创建/清理、失败回滚、进程中断恢复和保守清理。

### W2：Session / WebSocket 生命周期

- `new_chat` 在 attach 前完成 worktree 创建和 binding 持久化；耗时 Git 操作放入 worker thread，不阻塞 WebSocket event loop。
- `fork_chat`、session replay、scope resolver 和 delete API 接入 WorktreeManager，任何失败都不静默切换到原仓库。

### W3：WebUI

- Composer 增加 Direct/Worktree menu、HEAD 基线确认和结构化错误展示。
- 聊天/项目分组继续使用 source path，工具、文件预览和 artifact 使用 effective path。
- 增加受管 worktree 列表和非 force 安全清理操作。

### W4：文档与验收

- 更新总方案、本阶段 code note、`docs/修改记录.md` 和 WebUI 协议说明。
- 运行后端/前端定向回归、真实 Git 集成测试、ruff 和前端 build。

## 6. 测试与出口

- Direct 默认与所有 schema v1/旧 session 保持兼容。
- Git repo/subdir 可创建 worktree；非 Git、bare repo、branch/path 碰撞和变化的 expected HEAD 结构化失败。
- tracked/untracked 源变化要求显式 HEAD 确认；ignored 文件不阻断创建且不被复制。
- Worktree 聊天的工具 cwd、文件边界、artifact 路径、重启恢复和 UI 展示一致指向 effective path。
- Worktree 聊天不能改换项目/isolation mode；access mode 仍可在无运行任务时切换。
- clean fork 创建新 branch/worktree；dirty fork 拒绝且不创建残留 registry/path。
- 删除 clean+base worktree 会自动清理；dirty 或有新 commit 的 worktree 保留率 100%，不存在 force fallback。
- 两个并发 create/fork/cleanup 不会覆盖 registry 条目、复用 branch/path 或破坏另一个聊天的 worktree；进程在 `creating|removing` 中断后可对账。
- 伪造客户端 binding/common-dir/root 不能扩大 `WorkspaceScope` 或 sandbox roots。
- Worktree 不改变 P3 安全结论；Default Permission 仍由 Seatbelt/Bubblewrap 限制 effective workspace，Full Access 的风险仍明确由用户承担。
