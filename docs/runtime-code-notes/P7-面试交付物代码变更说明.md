## 尚未实现的交付闭环

### OfficePython

当前代码仍是 `office-automation` 窄工作流。后续 P1.1 将其直接改名为展示名 `OfficePython`、Skill id `office-python`，使用 `python-docx/lxml/openpyxl/python-pptx` 和单一 `scripts/office.py` JSON 入口提供通用 `inspect/query/create/apply/validate/render`；旧 DSL、专用 renderer 和周报 workflow 直接删除。

旧 id、显式路由和历史兼容入口不保留；启动时只清理 `disabledSkills` 中的旧 id。原周报 fixture 随旧 workflow 删除，测试改用新建的最小中立 fixture。代码、manifest 和测试完成前，P7 不得把 `OfficePython` 写成已实现能力。

### 公开 benchmark

首批固定三套：

| Benchmark | 证明范围 | 口径限制 |
| --- | --- | --- |
| OCB | DOCX/XLSX/PPTX 理解 | Langfuse Dataset + Terra Custom LLM-as-a-Judge，标记 `OCB/Mybot evaluation` |
| OfficeBench Office subset | Word/Excel 创建、读取、编辑和跨文件 | 原样运行官方确定性 evaluator，记录 `official_score` |
| PresentBench | PPT 生成、材料忠实度、内容和视觉质量 | Langfuse Dataset/media + Terra Custom LLM-as-a-Judge；视觉不支持时仅该维度本地 SDK evaluator fallback |

SpreadsheetBench Verified 暂列选做，用于未来高级 Excel 深度验证。三套结果不合成总分。

### 按 benchmark 固定 evaluator

1. OfficeBench Office subset：官方确定性 evaluator，`evaluation_source=officebench_official`，记录 `official_score`。
2. OCB：Langfuse Custom LLM-as-a-Judge 通过 OpenAI-compatible LLM Connection 调用 `gpt-5-6-terra`，`evaluation_source=langfuse_terra`，记录 `mybot_score`。
3. PresentBench：Langfuse Custom LLM-as-a-Judge + 必要 Annotation Queue；视觉媒体不支持时仅该维度由本地 SDK evaluator 计算，记录 `mybot_score`。
4. P5 Core Runtime hard gate、cassette 和红队仍作为独立回归证据，不计入 benchmark 分数。

OCB/PresentBench 不标记 `official-comparable`。P7 不采集业务对话量、满意度、CPU、内存和 GPU。只发布任务/benchmark 成功、LLM/tool 成功率与错误、P50/P95、Token/成本、Agent steps、等待/恢复和所选 evaluator 分数；人工结果保存在 Langfuse Annotation Queue，三套 benchmark 不合成总分。

### Langfuse

计划使用随 Mybot 默认安装且锁定版本的后端 Python SDK，复用其 OTel 上下文、observation 生命周期、`propagate_attributes()`、`mask_otel_spans`、batch/retry/flush、Experiment Runner 和 Scores API，而不是安装 Skill、使用前端 JS/TS SDK发送主 Trace，或自建通用 `TraceEvent/TraceSink` 协议：

```text
Mybot semantic instrumentation
  -> Langfuse SDK / OpenTelemetry context
       -> Langfuse Japan Cloud
            -> Trace / Dataset / Experiment / Score / Annotation Queue
```

Mybot 仍拥有采集点、`mybot.*` 语义、字段 allowlist、Runtime 状态和必须访问本地文件的 task/evaluator；Langfuse 负责 Trace/Sessions、Datasets/Dataset Runs、Experiments、Scores、LLM-as-a-Judge、Code Evaluator、成本/延迟 Dashboard、Annotation Queue 和失败下钻。它不替代 Runtime 状态和无 Key 本地硬门。

部署固定采用日本区 Langfuse Cloud，注册和 SDK endpoint 均为 `https://jp.cloud.langfuse.com`。账号、项目和 API Key 在日本区单独创建，不能把默认欧盟区账号当作可原地切换的同一环境。Cloud 模式不要求本机 Compose，也不要求下载 Redis、MinIO、ClickHouse 或 PostgreSQL。

启用 Cloud 后不持久双写生产 JSONL；Cloud 故障不会阻塞普通 Runtime，但不承诺离线 Trace 补传。`office-smoke/release` 必须通过日本区真实写入、flush、API 回读和 deep link smoke，否则 profile 失败。远程只接收脱敏 metadata；原始 Office 文件、完整正文、artifact、密钥和个人信息默认不上传。日本区属于跨境数据传输，真实公司或敏感数据在合规审查前保持 Cloud 关闭。

公开 benchmark 的人工审计使用 Langfuse Annotation Queue：smoke 12 个 case 全审，release 约 5% 分层抽样并额外全审高风险、异常、Terra 分歧和视觉 `unscored`。获许可的渲染图和 checklist 可上传；Score/comment/reviewer 直接保存在 Langfuse，私有 Office 内容不能进入该队列。

Mybot 不实现通用 Trace 查询、Dataset/Experiment CRUD、Score 分析、跨 run 图表或标注 UI。本地 benchmark CLI 只负责 Office 资产/依赖/license 准备、成本确认、调用 `run_experiment()` 和 `export --dataset-run`；Langfuse Dataset Run/Score/Annotation 是真相源，Git 只保存导出快照。

P5 Core 硬门在本地 pytest/CI 执行；OfficeBench 官方 evaluator、OpenXML/渲染检查作为 Langfuse `run_experiment()` 进程中的 SDK evaluator functions 执行并直接返回 Langfuse `Evaluation`。OCB/PresentBench 使用 Langfuse Custom LLM-as-a-Judge，不重复建设 Mybot Judge 或 Score 存储。

## 计划中的一键入口

```bash
nanobot benchmark prepare --profile office-smoke
nanobot benchmark prepare --profile office-release
nanobot benchmark estimate --profile office-release --model-preset gpt-5-6-luna
nanobot benchmark run --profile ci
nanobot benchmark run --profile office-smoke --model-preset gpt-5-6-luna
nanobot benchmark run --profile office-release --model-preset gpt-5-6-luna --presentbench-sample 50 --confirm-cost
nanobot benchmark export --dataset-run <langfuse-dataset-run-id>
```

- `ci`：确定性 eval、cassette、代表性红队、报告重生和 adapter contract；无网络、无真实模型、不开 Langfuse。
- `office-smoke`：三套公开集各 4 个固定分层 case，共 12 个且全部审计；两个 Skill 跑相同任务。
- `office-release`：OCB 全量、固定 OfficeBench subset；PresentBench 在 full/50%/25% 三档成本估算后确认并使用独立 Langfuse Dataset/series，换档不混合分母。

三套 adapter 共用一个独立 benchmark venv；`prepare` 固定最小精确 constraints、revision/SHA/license、外部数据和 LibreOffice 版本，`run` 不临时下载。fingerprint 写入 Langfuse Dataset/Experiment metadata，不在 Mybot 保存 run/Score 状态。运行前估算并二次确认成本。

release 顺序固定为 `prepare office-release -> estimate office-release -> run office-release`：prepare 缓存 OCB/OfficeBench release 数据和 PresentBench 三档候选资产，estimate 只读已准备数据，run 只消费选定 manifest。smoke prepare 不能替代 release prepare。

输出必须区分：

```text
benchmarks/runtime/   deterministic/fake-provider
benchmarks/office/    true-model public benchmark
benchmarks/exports/   从 Langfuse Dataset Run 导出的去敏快照
```

Langfuse Dataset/Experiment metadata 固定记录 benchmark revision、`evaluation_source`、git SHA/dirty、Skill id/digest、Luna/Terra preset、OfficeCLI/LibreOffice version/SHA、constraints、Judge/evaluator、Token、成本、延迟、tool success、Agent steps、artifact hash 和 trace id。原始数据、完整 trace、渲染图和大体积 Office 文件不提交 Git。

报告同时给出 `supported/total`、`passed/total`、`passed/supported`，unsupported 的成本/耗时单列。分数下降由 Langfuse Dashboard/CI regression gate 展示或阻断；`export` 只有在 Dataset Run 完成且 Annotation Queue 审核齐全时才更新 README 受控区块。

Mybot WebUI 不新增 benchmark 面板、实验状态机或人工评分按钮；用户直接在 Langfuse UI 查看 Experiment、Score、Dashboard 和 Annotation Queue，README/结果快照提供日本区 deep link。

## Office Skill 比较应怎样讲

P1.1 完成后，每次只启用一个被测 Skill，使用相同输入 snapshot、Luna、Policy、约束和 evaluator，输出两张表：

- capability coverage：`supported/unsupported/passed/failed`。
- common-task quality：OfficeBench official 或 OCB/PresentBench Mybot Score、Annotation Queue 结果、Token、LLM/tool latency、tool success、Agent steps。

OfficePython 是公平 Python baseline，不能为了体现 OfficeCLI 优势而人为阉割。OfficeCLI 的统一跨格式命令、DOM/query/batch/view/validate/raw、复杂文件覆盖和较少循环必须由真实数据证明。

## 当前禁止的表述

- “Langfuse Cloud 已接入”或“可观测已建立”：目前只确定日本区部署方案，没有 SDK observation、Dataset Run 和 Cloud smoke 证据。
- “Langfuse 已自托管”：项目已选择 Cloud，仓库不提供本地部署栈。
- “OfficePython 已是通用 Skill”：当前仍是 `office-automation` 窄工作流。
- “OfficeBench 总体官方分数”：只对固定 Office subset 原样运行官方 evaluator，并发布该 subset 的 `official_score`，不能外推为完整 300 任务总体分。
- “5 cases 代表真实模型质量”：它们是确定性 fixture。
- “OCB/PresentBench Mybot evaluation 可直接与官方榜单比较”：必须明确为 Terra 自评结果。
- “多个 benchmark 的平均值是 Office 总分”：不同任务和 evaluator 不可直接平均。

## 面试主线

> Mybot 先用 deterministic fixture 和 cassette 解决含 LLM 系统不可重复的问题，再用 Langfuse Dataset/Experiment 测 OCB、OfficeBench Office subset 和 PresentBench。OfficeBench 在 Experiment Runner 进程中调用官方 evaluator；OCB/PresentBench 使用 Langfuse Terra LLM-as-a-Judge，人工审核使用 Annotation Queue。Mybot 只负责 Agent/Office 执行和本地硬门，Langfuse 负责 Trace、Experiment、Score、Dashboard 和审核，让 OfficeCLI 与 OfficePython 在同一 Dataset 上比较覆盖、质量、成本和步骤数。
